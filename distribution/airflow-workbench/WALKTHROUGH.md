# 첫 평가부터 적용 구성까지

이 흐름은 이미 준비한 모델의 응답을 평가하고 사용 설정을 기록하는 과정입니다. 모델 가중치는 변경되지 않습니다. 실제 파인튜닝은 마지막의 별도 학습 경로를 따릅니다.

## 1. 설치와 권한 확인

README의 빠른 시작을 완료하고 `.env`의 관리자 계정으로 로그인합니다. 기존 설치를 점검할 때는 아래 명령을 사용하세요. 프로젝트·비밀번호·DAG 활성 상태를 바꾸거나 평가를 실행하지 않습니다.

```console
docker compose run --no-deps --rm airflow-init python /opt/workbench/scripts/verify_installation.py --existing
```

일반 계정은 `Viewer + WorkbenchAccess`로 플러그인에 접근하고 `ModelLabRunner`를 추가해 등록된 평가 DAG를 실행합니다. 프로젝트 owner/member 권한과 Airflow의 DAG 권한을 모두 갖춰야 합니다. 새 DAG를 추가했다면 그 DAG 권한도 부여하세요. Op/Admin은 전체 프로젝트를 볼 수 있고, 일반 계정은 자신이 소유하거나 공유받은 프로젝트를 봅니다.

## 2. 추론 연결 준비

환경·연결에서 기본 `Ollama` 카드를 확인합니다. 이 설치의 기본 연결 관계는 다음과 같습니다.

| 화면 항목 | 기본값 | 의미 |
| --- | --- | --- |
| 추론 연결 ID | `ollama` | Model Lab 평가 설정의 식별자 |
| Airflow 접속 정보 ID | `model_lab_ollama` | 서버 주소와 인증 정보를 찾는 키 |
| 평가 DAG | `model_lab_eval_ollama` | 평가를 수행하는 Airflow 작업 |
| 생성 파일 | `evaluation_ollama.py` | DAG 정의가 저장되는 파일 |

새 연결은 등록된 Connection을 선택하거나 ID를 입력합니다. 이름을 입력하면 DAG 이름과 파일을 미리 볼 수 있습니다. 환경변수·외부 Secrets Backend에서 공급한 Connection은 Airflow Connections 관리 목록에 없을 수 있으므로 카드의 출처를 확인하세요.

`DAG 생성·갱신` 후 DAG 목록 반영을 기다리고 `상태 새로고침`을 누릅니다. `평가 설정 점검: 설정 일치`를 확인한 뒤 DAG를 활성화하고 `모델 목록 확인`으로 사용할 모델이 있는지 확인합니다. 기본 DAG 메뉴, 내 대시보드, Model Lab에서 같은 DAG 권한으로 상태를 변경할 수 있습니다.

## 3. 프로젝트·평가셋·실험 생성

프로젝트 이름은 사람이 읽는 제목이며 ID는 설치 안에서 유일한 프로젝트 식별자입니다. 예를 들어 이름 `첫 수동 평가`, ID `manual-evaluation`을 사용합니다.

데이터·평가셋에서 생성 응답 평가용 사례를 준비합니다. 처음에는 `READY만 출력하세요` 같은 입력과 기대 문자열 `READY`를 가진 작은 평가셋으로 연결·채점 흐름을 확인하세요. 실험을 만들고 개선 목표를 기록합니다. 한 사례의 통과는 모델 전체 품질을 증명하지 않으므로 실제 업무 평가에는 다양한 사례와 별도 검증셋이 필요합니다.

## 4. 기준선과 후보 평가

실험에서 평가셋, 추론 연결, 준비된 모델을 선택합니다. 시스템 프롬프트 예시는 `추가 설명이나 문장부호 없이 사용자가 요청한 문자열만 출력하세요.`입니다. `평가 DAG 실행`을 누른 뒤 실행 탭에서 완료 상태, 각 사례의 실제 응답, 실패·미라벨 사례를 확인합니다.

| 실행 결과 버튼 | 다음 행동 |
| --- | --- |
| 기준선으로 지정 | 첫 정상 평가를 비교 기준으로 저장 |
| 설정으로 다음 후보 평가 | 프롬프트·모델·생성 설정을 바꿔 같은 평가셋으로 재평가 |
| 기준선과 비교 | 조건 통과율과 사례별 차이를 확인 |
| 모델 버전 등록 | 검토할 후보에 평가 결과와 모델 revision을 연결 |
| 결과 내보내기 | 평가 결과를 별도로 보관·검토 |

취소가 필요하면 실행 상세에서 취소를 요청합니다. 취소 요청 접수와 외부 작업 종료 확인은 다른 상태이므로 `취소 완료`까지 확인하세요. DAG 일시중지는 이미 실행 중인 작업의 취소 명령이 아닙니다.

## 5. 모델 버전 등록

버전 이름과 검토 메모를 입력합니다. 이미 준비한 기본 모델을 평가했다면 `연결할 학습 실행`은 `기본 모델 / 별도 준비 모델`로 두고 산출물 참조를 비워도 됩니다. 완료한 학습 실행이 있을 때 해당 실행을 연결합니다. 평가 결과에 모델 가중치가 들어가거나 등록 시 학습이 시작되지는 않습니다.

## 6. 검토 후 적용 구성 저장

모델·적용 구성에서 평가 근거와 모델 revision을 확인하고 검토 사유를 적은 뒤 승인하거나 반려합니다. 승인한 버전에 적용 대상 이름(예: `chatbot-development`)과 메모를 입력하고 검증 구성을 저장·내보냅니다.

내려받는 JSON은 모델명·revision·추론 연결 ID·프롬프트·생성 설정과 평가 근거를 전달하는 계약입니다. 모델 가중치나 Connection의 서버 주소·비밀번호·토큰은 포함하지 않습니다. 챗봇 개발자가 대상 환경에서 Connection ID를 실제 서버 연결로 해석하고 설정을 적용해야 합니다. 내려받기만으로 챗봇에 자동 배포되지는 않습니다.

## 별도 파인튜닝 경로

학습하려면 [WORKER.md](WORKER.md)에 따라 GPU 학습 워커와 Hugging Face 원본 가중치, 고정 revision, 학습·검증 데이터를 준비합니다. 저장소와 실행 환경 점검을 통과한 뒤 실험에서 학습 후보를 만듭니다. 학습 결과를 추론 엔진에서 사용할 수 있게 준비하고 같은 평가셋으로 다시 평가한 다음, 위 5~6단계에서 학습 실행과 평가 근거를 함께 연결합니다.
