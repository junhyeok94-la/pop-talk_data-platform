# 제출 거부 후 취소 대기 복구

`tester` 프로젝트의 `88e58af89110482f8e3705c77e33636e` 요청은 앞선 native POST 403 때문에 DAG가 생성되지 않았으나, 기존 `submission_unknown` 상태에서 `.cancel` 파일만 만들고 작업 종료를 기다렸다. 실제 Airflow metadata DB에 해당 DAG Run이 없고 평가 artifact도 없음을 확인했다.

사용자가 요청한 취소를 완료하기 위해 이 기록 1건만 버전 일치 조건으로 `cancelled`, `dag_run_created=false`로 정리했다. 이전 상태와 403 로그·metadata DB 대조 근거를 기록에 보존했다. 계정 역할과 다른 실행은 변경하지 않았다.

제출 거부가 확실한 요청은 취소 API에서 즉시 실행 전 취소를 완료하며, 상세 조회에서도 없는 DAG를 반복 조회하지 않는다. 취소 요청이 있는 실행은 같은 요청 ID로 재제출하지 않는다. 재시도 중 취소가 들어오면 외부 실행의 확인을 기다리고, 404나 통신 오류만으로 실제 작업이 중단됐다고 확정하지 않는다. 완료된 실행의 결과는 취소 요청으로 덮어쓰지 않는다.

검증: `test_model_lab_workflow`와 `test_airflow_workbench` 40개 통과. 실행 전 취소, 중복 취소, 취소 후 재제출 차단, 불확실한 404 상태 유지, 취소/재시도 경합, 완료 결과 보존을 검증했다. `lab.js` 문법 검사 통과.

이번 수정은 앞선 권한 수정에서 유지했던 기존 실행 기록을 사용자의 후속 취소 요청에 따라 복구한 것이다. 새 평가 DAG를 실행하지 않았다.
