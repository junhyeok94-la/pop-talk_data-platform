# 웹·백엔드 통합 검토 결과

검증일: 2026-09-09. 대상: 신규 DW 프로젝트의 apps 복사본과 로컬 Docker PostgreSQL. 기본 사용자 기능은 연결되어 있지만, 관리자 인증과 일부 데이터 표시·인증 로직에 결함이 있어 전체 정상 판정은 보류한다.

## 우선 수정할 결함

### 1. [P1] 관리자 직접 API에 인증·권한 검증이 없다

비로그인 상태에서 관리자 `/admin-api/members`, `/admin-api/reviews`, `/admin-api/movies`가 모두 HTTP 200과 데이터를 반환했다. 반면 WAS 관리자 API 및 관리자 `/api/members` 프록시는 401을 반환한다. 같은 관리자 앱 안에서도 요청 경로에 따라 보호 여부가 다르다.

근거: `apps/admin/src/app/admin-api/members/route.ts:17`. 회원 상태 변경 경로 `apps/admin/src/app/admin-api/members/[id]/status/route.ts:43`에도 인증 검증이 없는 것을 코드로 확인했다. 기존 회원 상태 변경은 실행하지 않았다. 관리자 화면의 슈퍼관리자 표시만으로 로그인된 것으로 판단할 수 없다.

현재 localhost 바인딩 환경에서 발견한 문제다. 직접 DB 경로 전체에 공통 서버 인증·역할 검증을 적용하거나, 인증이 있는 WAS로 관리 작업을 통합해야 한다. 조회와 쓰기 각각 익명·일반회원·관리자 권한 테스트가 필요하다.

### 2. [P2] 영화 상세 API가 국가·관람등급 필드를 누락한다

사용자 화면에서 영화 ‘듄’(ID 3374)의 국가·관람등급이 ‘미정’으로 표시된다. DB에는 미국·12세이상관람가가 있고 관리자 화면에는 정상 표시된다. WAS `apps/was/app/public_catalog.py:8`의 공통 SELECT 필드에 해당 값이 없다. FE는 `apps/fe/components/MovieDetailClient.tsx:119`와 `:123`에서 이를 사용한다.

공개 카탈로그 응답 계약에 해당 필드를 포함하고 목록 카드·상세 화면까지 확인해야 한다. 유형도 ‘미정’으로 보이지만 원천 값 존재 여부를 별도로 확인해야 한다.

### 3. [P2] 로그인 실패 횟수 업데이트가 롤백된다

테스트 계정으로 잘못된 비밀번호를 5회 연속 전송했으며 전부 401이었다. 직후 DB의 failed_login_count는 0, 잠금 상태는 false였다. `apps/was/app/auth.py:76`의 트랜잭션 안에서 실패 횟수를 업데이트한 뒤 `ProblemError`를 던지므로 변경이 롤백된다.

실패 횟수 변경을 커밋한 후 오류 응답을 반환하도록 수정하고 5회 실패 이후 잠금 및 잠금 해제 동작을 DB 통합 테스트로 검증해야 한다.

### 4. [P2] 관리자 운영 현황 문구가 실제 실행 상태와 다르다

`apps/admin/src/app/page.tsx:119`의 기준일은 2026년 8월 7일로 고정되어 있다. `:148`은 매일 02:00 수집이 돈다고 표시하지만 현재 Docker 구성에는 배치가 실행되지 않는다. DB 조회가 정상이어도 운영 현황 문구를 실제 파이프라인 상태로 볼 수 없다. 실제 실행 로그·최종 수집 시각으로 교체하거나 미구현 표시가 필요하다.

## 검증 결과

| 구분 | 결과 | 확인 범위 |
|---|---|---|
| 실행 환경 | 정상 | DB healthy, WAS·챗봇·사용자·관리자 컨테이너 실행 |
| API 통합 | 36건 중 33건 통과 | 실패 3건은 관리자 직접 API 익명 접근 |
| WAS 기존 테스트 | 14건 통과 | 테스트 프로세스에 테스트 전용 JWT_SECRET 지정 |
| 챗봇 기존 테스트 | 105건 통과 | 테스트 프로세스에 기존 테스트가 가정하는 CORS_ORIGINS=* 지정 |
| 사용자 브라우저 | 정상 | 로그인·로그아웃, ‘듄’ 검색 3건, 상세, 리뷰 작성·수정·삭제, 마이페이지 취향 및 삭제 반영 |
| 관리자 브라우저 | 조회 정상 | 대시보드 실제 DB 표시, 영화 검색 3건. 인증 정상이라는 의미는 아님 |
| 챗봇 브라우저·API | mock 연결 정상 | `"듄" 정보 알려줘` 입력 후 DB 영화 설명 표시, API 빈 입력 거절 |

API 검증에는 회원가입·중복 가입 거절·잘못된 비밀번호·토큰 갱신·취향 저장·익명 접근 차단·리뷰 중복 거절·0.5점 단위 검증·스포일러 제외·삭제 반영을 포함했다. 회원가입 전체 화면 흐름은 API 검증으로 대신했다.

기존 테스트를 실제 서비스 환경변수 그대로 실행하면 WAS 1건, 챗봇 2건이 테스트의 환경 가정 때문에 실패했다. 재실행 시 테스트 프로세스에만 값을 지정했고 실제 서비스의 JWT 키나 CORS 정책을 변경하지 않았다. 기존 테스트 통과는 위의 실제 통합 결함이 없다는 보장이 아니다.

## 데이터 정책 및 아직 검증하지 않은 범위

복원 기준 영화 5,319건, 리뷰 124,941건, 회원 317건, 영화 카테고리 14건이었다. 영화 테이블에서 개봉일이 2020년 이전인 데이터 570건, 다큐멘터리 장르 416건, PUBLISHED가 아닌 상태 10건을 확인했다. 공개 카탈로그에는 기획의 연도·장르 정책이 아직 일관되게 적용되지 않는다. 재개봉 포함 여부와 서비스 공개 상태 기준을 정한 뒤 필터를 검증해야 하며, 제작연도만으로 제외 여부를 결정해서는 안 된다.

챗봇은 mock 모드다. Gemini 생성 API·신규 로컬 임베딩·벡터 검색 정확도·전체 LangGraph 분기 성능을 검증한 결과가 아니다. 현재 응답에는 감독 배열이 그대로 표시되는 등 시연용 표현 정리도 필요하다. 추천 영역의 목록 표시 역시 개인화 추천 품질을 입증하지 않는다.

관리자 기존 데이터 쓰기, 부하 테스트, 운영 배포 빌드, 모바일·다중 브라우저 전수 검증은 수행하지 않았다.

## 이번 작업과 재현

- 호스트 8000 포트 충돌을 해결하기 위해 `compose.yaml`의 챗봇 외부 포트를 58000으로 변경했다. 기존 다른 프로그램은 종료하지 않았다. 내부 주소는 chatbot:8000이다.
- `scripts/integration-smoke.py`를 추가했다. 실행할 때마다 임시 QA 회원 1명이 생성된다. 이번 검증에서 DW_QA_TEST 회원 2명이 생성되어 로컬 DB에 남아 있다. 테스트 리뷰는 API와 화면에서 삭제했으며 소프트 삭제 흔적이 남을 수 있다. 사용자 브라우저는 로그아웃했다.
- 업무 코드의 위 결함은 수정하지 않고 재현·검토 결과로 기록했다. 원래 팀프로젝트 경로는 변경하지 않았다.
- 결과 파일은 이 문서 옆의 `integration-results.json`이다. 계정 비밀번호와 토큰은 보고서에 포함하지 않는다.

```powershell
docker --config .docker-local compose cp scripts/integration-smoke.py was:/tmp/integration-smoke.py
docker --config .docker-local compose exec -T was python /tmp/integration-smoke.py
docker --config .docker-local compose exec -T -e JWT_SECRET=test-secret-that-is-at-least-32-bytes was python -m pytest -q
docker --config .docker-local compose exec -T -e CORS_ORIGINS=* chatbot python -m pytest -q
```

스크립트는 기존 회원·리뷰를 수정하지 않고 자신이 만든 리뷰만 삭제한다. QA 회원은 UI 재현을 위해 남기므로 운영 데이터에 실행하는 용도가 아니다.
