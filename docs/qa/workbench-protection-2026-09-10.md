# 대시보드 운영 보호 검증

2026-09-10, Airflow 3.3.1 / PostgreSQL 17, 로컬 API 서버 1프로세스.

## 적용 결과

- 대시보드 전용 연결 풀·작업 스레드·HTTP 요청 한도, 전역 집계 1개·시작 간격 2초 적용.
- DB 연결 고갈·시간 초과·Lock 대기·활성 세션·API 이벤트 루프 지연에 따라 조회 보류.
- DB 부하 검사 중에는 API 진입부 잠금을 잡지 않도록 분리하고 회귀 테스트 추가.
- 같은 현재 권한·조회 조건의 만료 캐시만 제한적으로 반환. 다른 조건 또는 권한의 결과를 재사용하지 않음.
- 자동/수동 갱신의 Retry-After, 시간 분산, 마지막 조회 시각, 보류 안내 및 자동 갱신 꺼짐 유지.
- 초기 로딩 제한 시 다시 불러오기 제공. 필터 변경/권한 오류 시 이전 조건의 결과를 제거.
- 기존 PostgreSQL Workbench 테이블 13개·마이그레이션 v6 유지. 신규 계정/스키마 마이그레이션 없음.

Python 보호/성능 28개, 기존 모듈·계정·Studio·워크플로·조회 회귀 64개, 총 **92개 통과**.
JavaScript 갱신/탐색/테마 테스트 **9개 통과**. 변경한 스크립트 문법과 Python import 확인.

## 서로 다른 조건의 요청과 DB 쓰기 공존

프로덕션 기본 정책을 사용한 별도의 검증 프로세스다. 50,000행의 임시 PostgreSQL 테이블,
50개 다른 조건으로 1,000개 대시보드 요청을 20묶음에 나눠 보낸다. 동시에 native 경로에서
작은 UPDATE를 커밋한다. `wb_test_*` 스키마는 종료 후 정리한다. 업무 DAG는 실행하지 않는다.

| 측정 | 결과 |
|---|---:|
| 대시보드 요청 | 1,000회 |
| 정상 결과 / 보류 | 1 / 999 |
| 원본 집계 실행 / 동시 최대 | 1 / 1 |
| 대시보드 연결 풀 | 2개 |
| 작은 쓰기 기준선 p95 / 최대 | 41.61 / 70.54ms (80회) |
| 대시보드 부하 동반 쓰기 p95 / 최대 | 47.86 / 79.48ms (240회 모두 성공) |
| 대시보드 응답 p95 / 최대 | 0.76 / 180.51ms |

대부분의 요청을 빠르게 보류한 결과이며, 1,000회의 새 조회를 빠르게 처리했다는 뜻이 아니다.
별도의 작은 연결 풀이 소진되자 냉각 상태로 진입했다. 쓰기 지연 증가도 관측했으므로
공유 자원 영향이 0이라는 결론을 낼 수 없다. ASGI 함수 호출을 이용하며 실제 HTTP 네트워크,
인증 비용·스케줄러 heartbeat·배치 SLO를 재현한 실험은 아니다.

- [최종 측정 JSON](../../.local/qa/docs/workbench-protection-fixture-2026-09-10.json)
- 재현: `scripts/benchmark_workbench_protection.py`

## 실제 인증 및 적용 확인

실제 계정 JWT를 사용하는 새 Airflow 앱 프로세스에서 다음을 확인했다.

- 담당 DAG 7개, 차트 결과 7개 정상.
- Studio 초기 로딩의 보드/카탈로그/환경설정 3개 병렬 요청 정상.
- 검증 프로세스의 DB 혼잡 상태에서 대시보드는 503 + Retry-After.
- 같은 상태에서 native `GET /api/v2/dags`는 200.

[인증 검증 JSON](../../.local/qa/docs/workbench-protection-auth-2026-09-10.json). 이 검증의 혼잡 상태는 실제 API 서버에 주입하지 않았다.

실행 태스크·활성 상태인 실행 중 DAG·외부 학습 작업이 각각 0인 것을 확인한 뒤 API 서버만
재시작해 코드 적용. 기존 일시중지 DAG의 up_for_retry 1개는 그대로 유지됐다. 적용 후 실제
`work/summary`의 새 보호 응답과 메타 DB·스케줄러·트리거러·DAG 프로세서 healthy를 확인했다.

브라우저 검증에서는 플러그인 집계 슬롯을 QA 소유자로 최대 50초 예약했다. 캐시 만료 후
이전 결과와 기준 시각이 유지되고, 보류 안내와 새로고침 비활성화가 표시됐다. 예약 만료 후
사용자 조작 없이 결과 시각이 갱신되고 안내가 사라졌다. QA 소유자의 lease 잔여 행은 0개이다.
계정 필터·보드 편집과 DAG 실행/상태 변경 조작은 하지 않았다.

## 운영 범위

이는 로컬 운영 보호 기능 검증이다. 실제 조직의 여러 권한/사용자, 대규모 DAG 이력,
장시간 배치와 DB CPU/I/O 경합을 포함한 성능 승인과는 구분한다. 현재 core와 execution은
같은 API 프로세스이며, 네이티브 인증/권한 DB 연결은 Auth Manager의 경로를 사용한다.
강한 자원 격리와 운영 SLO 검증에 필요한 배포 조건은
[보호 정책 문서](../../orchestration/airflow/plugins/DASHBOARD_PROTECTION.md)에 명시했다.
