# 영화 기준선 대사 설계 재검토

판정: APPROVED — 읽기 전용 대사 모듈·실행 어댑터·테스트 구현을 시작할 수 있다. 이전 선검토의 주요 모순과 누락이 해소됐다. 실제 기준선 채택, bridge DDL 적용, Gold/서비스 게시 변경은 이번 승인 범위가 아니다.

## 이전 지적 반영 확인

| 지적 | 수정 내용 | 결과 |
| --- | --- | --- |
| 원천 ID당 단일 연결과 KMDb 공유의 모순 | 원천 identity와 current/history/candidate 분리, KOFIC 활성 연결 제한, 공유 KMDb 검수 격리 | 해소 |
| 불완전한 분류 및 건수 보존 | 문자열 ID 규칙, missing/invalid, 중복 그룹의 양쪽 전 행 격리, 원천별 배타적 행 수 보존식 명시 | 해소 |
| 기준선 판단 집계 부족 | 분류별 연도·정책·공개/승인/삭제 및 관계 영향, Gold ID와 publication/source 포함 3자 대사를 완료 조건으로 추가 | 해소 |

순수 대사에서 중복을 진단하기 전에 기존 legacy 변환의 중복 거부 검사를 적용하지 않도록 명시한 점도 적절하다. 원천 시각 미상/동시각 충돌을 자동 병합하지 않는 선택은 이번 읽기 전용 진단 범위에서 수용한다.

## 구현 시 확인할 세부 조건

아래는 설계 재승인을 기다릴 사유가 아니라 구현 검토의 확인 항목이다.

- **Gold 식별자의 의미:** 현재 Gold는 여러 source_run × artifact 관측을 통합한다. 전체 Gold를 단일 Exchange publication 하나로 표시하지 않는다. 영화 ID 추출과 같은 조회 결과에서 행별 source/publication 계보를 확보하고, 별도의 전체 게시 식별자를 사용한다면 그 의미와 추출 시각을 구분한다. 서로 다른 SELECT 결과를 혼합해 동일 버전으로 주장하지 않는다.
- **3자 대사의 완전성:** Gold가 legacy/service 어느 쪽에도 없거나 missing/invalid/ambiguous 그룹에 연결되는 경우도 미분류로 버리지 않는다. Gold 전체 건수까지 대사하고, casefold 충돌은 exact 분류와 별도의 진단이라는 점을 유지한다.
- **정규화와 정책:** 해시 전 줄바꿈·공백 정규화의 정확한 규칙, 문자열이 아닌 ID 입력 처리, boolean 허용값, 두 입력 필드의 정책 매핑을 코드와 fixture로 고정한다. 날짜 파싱 오류는 누락과 구분하고 정책 적격으로 자동 승격하지 않는다.
- **테스트:** §2.3의 예시뿐 아니라 양쪽 중복, 한쪽 중복+상대 단일 행, invalid/선행 0/case 충돌, 양쪽 필드 invalid, 원천별 행 수 보존식, manifest 변조 및 출력 민감정보 차단을 검증한다.
- **후속 bridge 제약:** 유효기간 중첩 금지는 동일 source identity의 상충 확정 연결을 대상으로 적용하고, 한 movie에 서로 다른 여러 source identity가 연결되는 것은 허용한다. 서비스 history는 service_system × service_movie_id 기준으로 중첩을 금지한다. 이번에는 계약 기록까지만 수행한다.

## 승인 범위와 다음 완료 판정

수정 설계 전체를 이전 선검토 보고서와 대조했다. 이번에는 외부 데이터 조회나 업무 코드 변경을 하지 않았다.

다음 결과물은 순수 모듈, 읽기 전용 어댑터, 테스트, 실데이터 집계 및 기준선 채택 제안이다. 실행 결과를 보고 채택 범위와 남은 미결정 계약을 판단한다. 충돌이 발견됐다는 이유로 임의 수정·자동 매칭·게시까지 진행하지 않는다. 설계 단계의 CHANGES REQUESTED는 본 수정본에 대해 APPROVED로 대체한다.
