# 공통 담당 범위·검색·자동 갱신 검증

환경: Airflow 3.3.1 / 기존 PostgreSQL / 로그인된 로컬 브라우저.

## 변경

- 담당 DAG와 차트·추세가 계정별 담당 DAG·태그·검색어·실행 상태·활성 상태·기간을 공유한다.
- 검색은 공백으로 나눈 단어를 모두 만족해야 하며 DAG ID·표시 이름·태그·소유자를 대상으로 한다.
  담당 범위 밖의 DAG를 추가하지 않는다. 초기화는 검색·상태만 지우고 담당 범위와 기간은 유지한다.
- 자동 토글과 30초/1분/5분 간격, 접근성 이름이 있는 수동 SVG 아이콘을 공통 제공한다.
  자동 갱신을 끈 상태도 계정에 저장되며 숨김·입력·패널 편집 중 주기 조회를 쉬도록 한다.
- Studio는 기본적으로 담당 범위를 사용하고, 연결할 수 없는 SQL/MLOps 소스는 별도 분석을
  명시적으로 선택해야 한다. 기존 보드·패널·권한·캐시 정책은 유지한다.

## 자동 검증

- Python 46개 통과: performance / workflows / modules / studio.
- 링크·테마 JavaScript 7개 통과. 수정한 JavaScript 구문 검사 통과.
- 실제 격리 PostgreSQL에서 담당 태그와 권한의 교집합, 다중 검색어·소유자·활성 필터,
  담당 목록과 차트의 동일 실패 건수, 프로필 기간 우선, 필터 변경 후 캐시 분리,
  빈 검색 결과의 0건 유지, 공유 모드에서 직접 SQL 미실행을 검증했다.
- 실패 필터를 적용해도 마지막 성공 시각을 보존하는 보완 후 관련 집계 2개를 재검증했다.

## 브라우저 검증

- 검색 `movie databricks` + 실패 + 일시중지를 적용해 담당 DAG 1개, 실패 실행 8건을 확인했다.
- 차트로 이동해 같은 조건과 실패 8건이 표시되는 것을 확인했다. 이전 전체 조회는 섞이지 않았다.
- 차트 실행 이력의 Run ID를 클릭해 native Airflow 실행 breadcrumb가 표시되고 플러그인 iframe은
  사라지는 것을 확인했다. 분석 결과에서 원본 실행·로그로 이어진다.
- 자동 갱신을 끄고 탭을 바꿔도 꺼짐 상태가 유지되었다. 30초보다 긴 시간 후에도 갱신 시각이
  그대로였으며, 수동 아이콘을 클릭하면 새 갱신 시각으로 바뀌었다.
- 차트에서 결과 없는 검색어를 적용했을 때 담당 범위 0개와 집계 0건을 확인했다.
  담당 탭에서도 동일한 빈 조건과 필터 초기화 안내를 확인했다.
- 필터 초기화 후 자동 갱신을 켜 원래 조회 조건으로 복원했다. 업무 DAG를 실행하거나
  활성 상태를 변경하는 시험은 수행하지 않았다.
- 자동 갱신을 다시 켠 후 표시 기준 시각이 17:50:30에서 17:51:00으로 진행됨을 확인했다.
  개인 설정은 v13이며 담당 태그 `pop-talk`, 168시간, 장기 실행 60분, 빈 검색/상태 조건,
  모든 활성 상태, 자동 30초로 원래 값을 복원했다. 기존 개인 보드 v9는 유지했다.

담당 탭의 진행 중 작업은 기간 밖도 포함한다. 차트는 기간 안의 실행 이력만 집계하므로
기간 경계를 넘는 running/queued 건수 차이는 의도된 동작이다. 공유 범위와 별개인 패널별
추가 조건도 집계에 적용한다. 사용자 입력 SQL을 임의로 재작성해 DAG 권한 필터를 삽입하지 않는다.

## 공통 필터 위치 보완

- 두 페이지의 실제 문서 순서를 제목 → 공통 조회 범위·조건 및 갱신 → 탭 탐색 → 본문으로 변경했다.
  공통 영역은 탭 본문 `#app` 바깥에 있으며, 중복 페이지 제목도 제거했다.
- 브라우저의 접근성 트리와 화면 캡처에서 두 탭 모두 이 순서를 확인했다.
  동일한 7개 담당 DAG, 빈 검색, 모든 실행/운영 상태, 최근 7일, 자동 30초가 유지되었다.
- 변경한 JavaScript 3개 구문 검사를 통과했다. 이번 보완은 화면 배치와 문구 변경이며
  설정 저장, 업무 DAG 실행·상태 변경은 수행하지 않았다.
