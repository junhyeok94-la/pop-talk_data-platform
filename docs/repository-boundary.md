# 저장소 간 데이터 계약

| 소유자 | 책임 |
|---|---|
| pop-talk_application | 웹·WAS·챗봇, 서비스 `dev` DDL과 마이그레이션, 회원·리뷰·관리자 수정·승인 |
| pop-talk_data-platform | 원천 보존, 수집 이력, 식별·매핑, STG/DW/Mart, dbt 검사, 게시 실행 |

서비스 DDL은 application의 `apps/was/migrations`가 실행 기준입니다. 플랫폼에 복제하지 않습니다.
플랫폼의 PostgreSQL은 서비스 DB와 별도 볼륨을 사용합니다. 소스 파일을 서로 import하거나 mount하지 않습니다.

## 영화와 흥행 게시

- 영화는 KOFIC 코드로 매칭하고 기존 `popcorn_movies.id`를 보존합니다.
- 서비스 DB의 `reviews.movie_id` 등 FK가 가리키는 영화를 전체 교체하지 않습니다.
- 신규 영화는 DRAFT/PENDING으로 게시하며 관리자 승인 상태를 자동으로 바꾸지 않습니다.
- 원천 소유 필드만 변경하고 관리자 보정·리뷰·미디어를 보존합니다.
- 영화·흥행·성공 이력은 한 트랜잭션에 반영합니다. 실패하면 기존 정상 데이터가 남습니다.
- 동일 입력 재실행은 중복을 만들지 않고 오래된 입력은 최신 결과를 덮어쓰지 않습니다.

## 리뷰·평점 추출 (Phase 1 예정)

읽기 전용 연결로 필요한 컬럼을 추출하고 리뷰 ID·영화 ID·출처·작성/수정/삭제 시각을 보존합니다.
내부 회원과 외부 작성자를 같은 사용자로 결합하지 않습니다. 플랫폼이 게시한 분석 결과를
리뷰 원천으로 다시 수집하지 않습니다. 현재 분리 커밋에는 신규 리뷰 추출 DAG가 구현돼 있지 않습니다.

## 실행 경계

각 저장소의 `.env`와 `.local/config`는 로컬에서 따로 관리합니다. DB 덤프·모델·인증키는 Git에 넣지 않습니다.
샘플·백업을 필요로 하는 도구는 명시적인 파일 인자를 받습니다. 다른 저장소의 로컬 경로를 기본값으로 삼지 않습니다.
