# 아이도 이해할 수 있는 Pop Talk DW 이야기

작성일: 2026-09-08 · 최종 갱신: 2026-09-09 · [상세 설계안](project-plan-and-architecture.md)의 쉬운 설명

## 1. 우리는 무엇을 만들까?

영화 정보가 아주 많은 도서관을 만든다고 생각해 보세요.

어떤 공책에는 영화 제목과 관객 수가 있고, 다른 공책에는 줄거리와 배우가 있어요. 또 다른 공책에는 사람들이 준 별점이 있어요. 같은 영화인데 공책마다 이름이나 번호가 다를 수도 있어요.

우리는 이 공책들을 정리해서 **같은 영화의 정보를 연결하고, 숫자를 정확히 계산하고, 질문에 답하는 도서관**을 만들 거예요.

예전에 만든 두 화면을 다시 연결해서 사용할 거예요.

- 사용자 화면(pop_talk_fe): 영화를 둘러보고, 영화 정보나 취향에 맞는 영화를 챗봇에 물어볼 수 있어요.
- 관리자 화면(pop_talk/apps/admin): 기존 관리 기능에 더해 어떤 영화가 인기 있었는지, 자료가 얼마나 잘 모였는지 보여줘요.

챗봇을 로컬에서 실행한다는 것은 별도 화면만 새로 만든다는 뜻이 아니에요. 기존 화면 뒤에서 일하는 챗봇 프로그램과 모델을 집 컴퓨터에서 실행한다는 뜻이에요.

### 예전에 만든 프로그램은 어떻게 나눠 일할까?

| 프로그램 | 도서관에 비유한 역할 |
|---|---|
| pop_talk_fe | 이용자가 보는 안내 화면이에요. |
| pop_talk/apps/admin | 관리자가 쓰는 업무 화면이에요. |
| pop_talk_was | 두 화면에서 오는 일반 업무를 처리하는 창구예요. |
| pop_talk_chatbot | 자연어 질문을 해석하고 자료를 찾아 설명하는 안내 직원이에요. |
| pop_talk_batch | 밖에서 영화 자료를 모아 오는 담당자예요. |

새 DW는 이 담당자들이 사용할 자료를 정리하고 분석하는 자료실이에요. 기존 프로그램을 버리고 모두 새로 만드는 계획은 아니에요. 다시 연결하는 데 필요한 부분을 확인하고 고쳐요.

## 2. 도구들은 무슨 일을 할까?

| 어려운 이름 | 쉬운 설명 |
|---|---|
| 원천 파일·S3 같은 저장소 | 처음 받은 공책을 보관하는 창고예요. S3는 무료 크레딧으로 쓸 수 있을 때 선택해요. |
| Databricks·PySpark | 많은 자료를 나눠 정리하는 작업장이에요. 무료 작업 시간에는 제한이 있어요. |
| Bronze | 받아 온 자료를 출처와 함께 보관하는 칸이에요. |
| Silver | 글자·날짜를 정리하고 같은 영화를 연결한 칸이에요. |
| Snowflake·DW | 분석하기 쉽게 정리된 자료실이에요. |
| dbt | 자료실의 숫자를 계산하고 잘못된 자료가 없는지 검사하는 설계도예요. |
| Airflow | 어떤 일을 먼저 하고, 실패한 일을 언제 다시 할지 관리하는 시간표예요. |
| PostgreSQL | 화면과 챗봇이 빨리 읽을 수 있게 필요한 결과를 담아 놓는 서랍이에요. |
| 임베딩·pgvector | 글의 뜻을 숫자로 표현하고 비슷한 뜻의 글을 찾는 도구예요. |
| LangGraph | 질문에 따라 어느 도구를 사용할지 연결한 길 안내도예요. |
| Gemini 생성 모델 | 찾아온 자료를 사람이 읽기 쉬운 문장으로 설명해요. 보내기 전에 사람을 알아볼 수 있는 정보는 빼야 해요. |

Airflow 시간표만 있다고 같은 자료가 두 번 들어가는 일이 자동으로 사라지지는 않아요. 자료를 넣는 프로그램도 “이미 넣었는가?”를 확인해야 해요.

## 3. 영화가 6천 개면 너무 적지 않을까?

책이 6천 권 있다고 생각해 보세요. 책마다 읽은 사람들의 평가가 여러 개 있고, 날짜별 대출 기록도 있을 수 있어요. 책 목록은 6천 줄이어도 기록은 훨씬 많을 수 있죠.

영화도 같아요. 영화 목록과 평점 기록은 크기가 달라요. 중요한 것은 숫자를 억지로 늘리는 일이 아니라 **누구의 어떤 기록인지 정확히 연결하는 일**이에요.

MovieLens의 약 3,200만 건은 긴 감상문이 아니라 별점 기록이에요. 그리고 그중 우리 영화 목록과 연결되는 기록이 몇 개인지는 조사해야 해요. 오래된 자료라 최근 영화의 평가가 없을 수도 있어요.

## 4. 같은 영화인지 어떻게 알까?

한 공책에는 한글 제목, 다른 공책에는 영어 제목이 적혀 있을 수 있어요. 제목이 같아도 다른 영화일 수 있어요.

그래서 제목뿐 아니라 감독, 제작연도, 개봉일 같은 단서도 확인해요. 같은 영화라고 확인하면 우리 도서관의 공통 번호를 붙여요. 확실하지 않으면 억지로 합치지 않고 “확인 필요” 상자에 넣어요.

배우도 이름이 여러 방식으로 적힐 수 있어요. 이름표를 잘 연결하면 한글·영문·다른 표기로 물어봐도 같은 사람을 찾는 데 도움이 돼요. 동명이인은 따로 확인해야 해요.

## 5. 챗봇은 질문마다 다른 방법을 써요

### “젠데이야가 나온 영화 알려줘”

배우가 누구인지 확인하고 출연작 목록을 찾아요. 줄거리의 뜻이 비슷하다는 이유만으로 출연작이라고 말하면 안 돼요.

### “따뜻하고 잔잔한 영화 추천해 줘”

줄거리의 뜻을 비교해서 어울리는 영화를 찾아요. 이것이 임베딩 검색이 도움이 되는 질문이에요.

### “그중 두 시간보다 짧은 영화는?”

방금 말한 영화들을 기억하고 상영시간 조건을 적용해요.

### “이 영화 평점과 사람들 반응은?”

평점 기록과 실제 리뷰가 있는지 확인해요. 리뷰가 없으면 별점만 보고 감상문을 지어내지 않아요.

찾는 것과 설명하는 것은 달라요. 먼저 근거를 제대로 찾고, 그다음 모델이 설명해요. 마지막에는 조건과 숫자가 맞는지 검사해요.

### 챗봇도 연습해서 나아질 수 있어요

처음에는 Gemini가 질문을 정리하고 답변을 만드는 기준 선생님 역할을 해요. 집 컴퓨터에서는 Qwen3라는 작은 모델도 같은 문제를 풀어 봐요. 틀린 문제를 모아 사람이 올바른 질문 계획과 답변을 적어 주면, QLoRA라는 방법으로 모델 전체가 아니라 작은 추가 학습 파일만 만들 수 있어요.

영화 줄거리나 최신 평점을 모델에게 외우게 하지는 않아요. 그런 사실은 계속 바뀌므로 DW 자료실에서 찾습니다. 로컬 모델은 “배우 이름은 어느 칸에 넣을지”, “자료가 없으면 모른다고 말할지”처럼 일하는 방법을 배워요.

## 6. 숫자도 조심해서 읽어야 해요

월요일까지 총 관객이 100명이고 화요일까지 총 관객이 150명이면, 둘을 더해 250명이라고 하면 안 돼요. 이미 월요일 관객이 화요일 총합에 들어 있기 때문이에요.

또 자료에 어떤 영화가 없다고 관객이 0명이라는 뜻은 아니에요. 우리가 가져온 목록 밖에 있을 수도 있고 수집에 실패했을 수도 있어요. 그래서 화면에는 자료의 날짜와 범위를 함께 보여줘요.

## 7. 무료 체험으로 어떻게 끝낼까?

무료 작업 시간을 쿠폰이라고 생각하면 쉬워요. 쿠폰은 양과 기간이 정해져 있어요.

처음에는 적은 자료로 길이 잘 연결되는지 확인해요. 성공하면 조금 더 큰 자료를 처리해요. 같은 큰 작업을 이유 없이 반복하지 않아요. 추가 결제로 해결하지 않고 남은 쿠폰에 맞춰 확장 기능을 줄여요.

집 컴퓨터는 기억 공간이 RAM 32GB이고, 모델 계산을 돕는 GPU에 12GB 공간이 있어요. 영화와 리뷰를 숫자 지도인 임베딩으로 바꾸는 일은 집 컴퓨터가 합니다. 찾아낸 자료를 문장으로 설명하는 일은 우선 Gemini가 맡고, 나중에는 학습한 Qwen3도 같은 일을 해 보며 결과를 비교해요.

모델 원본과 학습 파일은 E 드라이브 창고에 모아 둬요. 하지만 E 드라이브에서 큰 모델을 바로 읽으면 너무 느렸어요. 그래서 자주 사용하는 모델의 사본은 D 드라이브 책상 위에 두고 실행해요. E는 안전하게 보관하는 창고이고 D는 빠르게 일하는 책상인 셈이에요.

쿠폰이 끝나기 전에 정리한 자료와 검색 결과를 집 컴퓨터에 저장해요. 그 뒤에는 **마지막으로 저장한 날짜의 자료**로 화면과 챗봇을 보여줄 수 있어요. 클라우드가 계속 새 자료를 처리하고 있다는 뜻은 아니에요.

## 8. 잘 만들었는지 어떻게 확인할까?

학교 공통 시험처럼 여러 모델이 함께 풀어 보는 공개 시험이 있어요. 이 시험으로 한국어를 이해하고 일반 문제를 푸는 기본 실력을 비교할 수 있어요. 하지만 공개 시험에는 우리 영화 자료와 화면이 없으므로 그것만으로 Pop Talk를 잘 만들었다고 할 수는 없어요.

그래서 우리만의 **영화 문제집(Golden QA)**도 만들어요. 자료실에서 SQL로 정답 영화와 숫자를 먼저 찾고, 그 결과를 문제의 정답표로 저장해요. “젠다야가 나온 2020년 이후 영화”처럼 이름이 조금 다르거나 조건이 여러 개인 문제, 자료가 없어서 모른다고 해야 하는 문제도 넣어요. 처음에는 60~100문제로 길이 제대로 연결되는지 보고, 모델을 학습해 비교할 때는 150~300문제로 늘려요.

연습에 사용한 문제로 다시 시험을 보면 외운 것인지 실력이 늘어난 것인지 알 수 없어요. 그래서 연습 문제, 중간 확인 문제, 마지막 시험 문제를 나누고 마지막 시험 문제는 QLoRA 학습에 넣지 않아요.

- 같은 공책을 두 번 넣어도 기록이 두 배가 되지 않는가?
- 중간에 멈춰도 다시 시작해서 끝낼 수 있는가?
- 서로 다른 영화를 잘못 합치지 않았는가?
- 배우명뿐 아니라 분위기·시간·장르·이전 대화를 이해하는가?
- 자료가 없으면 없다고 말하는가?
- 화면의 숫자가 원래 자료와 맞는가?
- 무료 쿠폰 안에서 끝났는가?

이번 프로젝트는 **영화 자료를 믿을 수 있게 정리하는 과정이 중심**이에요. 기존 사용자 화면의 영화 탐색·챗봇과 관리자 화면의 분석 기능을 통해 그 자료가 실제로 도움이 되는지 보여줘요.
