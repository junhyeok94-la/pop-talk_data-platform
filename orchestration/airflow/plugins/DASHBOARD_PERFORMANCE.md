# 내장 대시보드의 조회 성능

목표는 Airflow 웹에서 별도 로그인·이동 없이 조회하면서, 화면 수에 비례하는 원본 이력 반복 조회를 억제하는 것이다. 차트·레이아웃 라이브러리는 플러그인에 포함한다. 별도 대시보드 서버, Grafana, Prometheus, SQLite, 신규 DB 계정은 필요하지 않다.

## 담당 DAG와 운영 모니터링

`내 대시보드 → 담당 DAG`는 직접 선택·업무 태그와 현재 DAG 권한의 교집합에 대해서만
실행 이력을 읽는다. 최대 200 DAG·30일 범위이며, 그 이전에 시작된 running/queued 실행도
놓치지 않도록 포함한다. 상태별 건수·최근 상태·마지막 성공·주의 목록·최근 실행을
한 SQL의 materialized CTE로 계산하고 기존 30초 캐시·동시 집계 1개 제한을 공유한다.
주의 목록은 최근 100개, 최근 실행은 30개까지 표시한다. 담당 DAG 메타데이터와 권한 검사는
매 요청 수행하며, 캐시 적중이 메타 DB 조회 전체를 없애는 것은 아니다.

기본 화면은 차트 번들을 로드하지 않는다. 목록과 현재 화면에서 요청한 실행 추적은 계정의 갱신 간격(기본 30초)으로 갱신하며 숨겨진 탭·대화상자에서는 멈춘다. 실제 재실행의 권한·상태·대상 검사는
캐시를 사용하지 않고 native API에서 다시 확인한다.

별도 `운영 모니터링` 메뉴는 등록된 URL의 iframe만 렌더링한다. 표시 중에는 플러그인에서
메트릭을 수집하거나 Airflow 이력을 주기적으로 조회하지 않는다. 외부 화면의 갱신·저장·부하는
연결된 서비스의 책임이다.

## 차트·추세의 현재 구현

Airflow 실행 이력 데이터 소스의 요청 경로:

```text
Airflow 로그인·Plugins 권한
  → 현재 Auth Manager의 RUN 조회 허용 + 허용 DAG 목록 확인
  → 권한 범위·기간·변수·집계 정의로 캐시 키 생성
  → 기존 PostgreSQL workbench.dashboard_cache 조회
      ├─ 유효한 결과: 차트에 필요한 집계 결과 반환
      └─ 결과 없음: 동시 집계 슬롯 확보
           → 허용 DAG와 시간 범위로 원본을 제한
           → 하나의 materialized CTE를 모든 패널에서 재사용
           → PostgreSQL에서 필터·그룹·집계·정렬
           → 작은 결과만 저장·반환
```

- 원본 실행 이력을 100건씩 API로 받아 Python에서 계산하던 기본 경로를 제거했다. 원본 `DagRun` 전체 객체·conf·관계 데이터도 반환하지 않는다.
- count/sum/avg/min/max/P95/일치 비율과 시간 버킷을 SQLAlchemy 표현식으로 생성한다. 사용자 SQL 문자열을 이 경로에서 실행하지 않는다. P95는 `percentile_disc`로 기존 nearest-rank 의미를 유지한다.
- 원본 5,000건 제한 없이 선택 기간 전체를 집계한다. 표·그래프 결과에는 최대 2,000행 제한과 표시가 남는다. 소규모 표본으로 전체 기간 통계를 대신하지 않는다.
- PostgreSQL의 `WITH ... AS MATERIALIZED`는 **한 SQL 실행 안에서만 쓰는 중간 결과**이다. 영구 materialized view·증분 집계 테이블·자체 TSDB를 만든 것은 아니다.
- 결과 캐시는 최대 30초이며 상대 시간 범위 끝을 30초 경계로 맞춘다. 패널에 실제 조회 기준 시각이 표시된다. 브라우저 자동 갱신은 계정 설정(기본 30초)을 따르며, 숨겨진 탭·편집 중에는 중지한다.
- 동일한 현재 DAG 권한·조회 조건이면 사용자·API 프로세스 사이에서도 결과를 공유한다. 보드 소유권과 레이아웃은 계속 계정별로 분리한다. RUN 권한과 허용 DAG 목록은 캐시 적중 시에도 재검사한다.

## 부하 제한

| 대상 | 제한 |
|---|---|
| 원본 집계 SQL | 읽기 전용 트랜잭션, statement timeout 1초, lock timeout 100ms, 병렬 워커 0 |
| 동시에 실행되는 원본 집계 | 같은 workbench 스키마의 전체 API 프로세스 합계 1개, 새 집계 시작 간격 최소 2초 |
| 동일 요청 | 프로세스 내부 실행 병합; 다른 프로세스의 집계 중에는 이전 결과 또는 갱신 보류 반환 |
| 캐시 공간 | 최대 32개 키, 값당 UTF-8 JSON 2MiB; payload 합계 최대 약 64MiB |
| 프로세스 중단 복구 | 10초 lease 만료 후 다른 요청이 재시도; 이전 소유자의 결과 덮어쓰기 차단 |
| 대기 | DB 반복 폴링 없음; 이전 결과 또는 503 + Retry-After |
| API 자원 | 프로세스당 요청 4개·초당 4회, 작업 스레드 4개, 전용 DB 연결 2개 |

캐시 claim·slot 예약은 짧은 트랜잭션으로 커밋한 후 집계를 실행한다. 혼잡한 요청은 대기 큐에 쌓지 않고 즉시 갱신을 미룬다. 세부 기본값과 한계는 [운영 보호](DASHBOARD_PROTECTION.md)를 따른다. 공간 수치는 JSON payload 기준이며 PostgreSQL 인덱스·행 버전·WAL 등의 실제 디스크 사용량 상한은 아니다. `work_mem=4MB`는 정렬·해시 작업별 설정이며 프로세스 전체 메모리 상한이 아니다.

## 적용 및 호환

- Airflow 3.3.1/PostgreSQL 환경에서 검증했다. 기본 Airflow 모델 테이블은 읽기만 하고 `workbench.dashboard_cache` 테이블을 추가했다. 기존 `leases` 테이블은 집계 동시성 제어에도 사용한다.
- 새 설치·업데이트 시 `PYTHONPATH=/opt/airflow/plugins python -m airflow_workbench.metadata`를 먼저 실행하고 API 서버를 재시작한다. DAG processor·triggerer 변경은 필요하지 않다.
- 네이티브 DAG 필터와 동일하게 `is_authorized_dag(GET, RUN, DagDetails(id=None))`, `get_authorized_dag_ids(GET)`를 적용한다. 다른 Airflow 버전·Auth Manager로 배포할 때 실행 조회 권한 의미와 `DagRun` 컬럼 호환성을 검증해야 한다. 이 어댑터는 **현재 Airflow의 메타 DB**를 조회한다.
- 별도 분석의 직접 SQL·이전 실험 소스도 현재 사용자·권한·설정별 캐시와 전역 집계 예산을 사용한다. 직접 SQL의 읽기 전용 Connection 조건을 유지한다. 이전 실험 소스는 원본이 5,000건을 넘으면 집계를 중단하고 기간 축소를 안내한다.

## 확인된 수치와 한계

아래는 **운영 보호 추가 전** 2026-09-10 로컬 환경의 단기 측정이다. 현재 버전은 과도한 동시 조회에 503을 반환하므로 아래의 전 요청 성공 수치를 현재 처리량으로 해석하면 안 된다. 두 측정은 데이터 크기와 인증 비용이 달라 직접 성능 비교 대상으로 삼으면 안 된다.

| 측정 | 동시 조회 | 최초 묶음 p95 | 재조회 묶음 p95 | 원본 재사용 |
|---|---:|---:|---:|---|
| 격리 PostgreSQL 50,003건·7패널, 서버 함수 경로 | 20 | 400.4ms | 16.1ms | 40회 요청에 원본 집계 SQL 1회 |
| 현재 Airflow 인증 HTTP·실제 이력 44건·7패널 | 20 | 295.6ms | 146.6ms | 최초 19/20, 재조회 20/20이 결과 재사용 |

첫 측정의 권한 객체는 테스트용이다. 두 번째는 실제 계정 하나의 동시 HTTP 요청이다. 브라우저 렌더링 시간, 여러 실제 계정의 권한 구성, 장시간 부하, 대규모 DAG 실행과의 자원 경합을 포함하지 않는다. 권한 축소·빈 권한·프로세스 간 lease·실패 복구·캐시 크기는 별도의 PostgreSQL 회귀 테스트로 검증한다.

이 구조도 캐시 miss마다 메타 DB 원본을 읽는다. 초 단위 GPU/CPU 메트릭 수집이나 장기 시계열 저장 기능은 아니며, 메타 DB와 CPU·I/O를 공유한다. 더 큰 규모에서는 측정 결과에 따라 증분 집계나 기존 메트릭 백엔드 어댑터를 추가한다. 화면은 계속 Airflow 플러그인에 유지할 수 있다.

재현 스크립트:

- `orchestration/airflow/tests/test_workbench_performance.py`: 실제 격리 PostgreSQL 스키마 기반 정확성·권한·동시성 테스트.
- `orchestration/airflow/tests/benchmarks/benchmark_workbench_dashboard.py`: 50,003행 격리 fixture, 측정 후 테스트 스키마 정리.
- `orchestration/airflow/tests/smoke/smoke_workbench_dashboard_performance.py`: 현재 저장된 보드로 인증 HTTP 조회; 보드 설정·DAG 실행 변경 없음.

운영 보호 추가 후 재현·측정은 [보호 정책과 검증](DASHBOARD_PROTECTION.md)을 참조한다. 기존 HTTP burst 스크립트는 과거 캐시 측정용이며 현재의 보류 응답을 허용하는 벤치마크가 아니다.
