# Airflow Workbench 화면 사용 안내

Airflow 왼쪽 메뉴의 **내 대시보드**, **운영 모니터링**, **Model Lab**에서 사용합니다.
상단 Workbench 메뉴 없이 Airflow에 로그인한 상태로 열립니다. 공통 화면의 명칭은
Airflow Workbench이며, 목록에 나타나는 DAG·모델·실행 환경 이름은 연결된 환경의 실제 데이터입니다.

FAB 인증 관리자에서 Viewer/User에게 메뉴를 제공하려면 별도 역할(예: `WorkbenchAccess`)에
`menu access on Plugins`와 `can read on Plugins`를 모두 추가하고 기존 역할과 함께 부여합니다.
메뉴 표시 권한과 플러그인 API 조회 권한은 별개입니다. 기본 Viewer 역할을 직접 수정할 필요는 없습니다.
이 권한은 세 플러그인 메뉴의 공통 진입 권한이며, DAG 변경 권한이나 Model Lab 프로젝트 권한을
추가로 부여하지 않습니다.

Airflow **사용자 → 외관**에서 **라이트 모드 / 다크 모드 / 시스템 설정 따르기**를
선택하면 대시보드와 Model Lab도 새로고침 없이 함께 바뀝니다. 차트의 축·범례·툴팁,
SQL 편집기, 입력창과 대화상자에도 적용됩니다. 편집 중인 입력과 차트 확대 범위는
유지되며, 패널에서 직접 지정한 데이터 색상도 유지합니다.

## 내 대시보드 · 담당 DAG

**담당 범위 설정**에서 DAG를 직접 고르거나 업무 태그를 입력하고 저장합니다.
현재 계정이 조회할 수 있는 DAG 중 직접 선택과 태그에 해당하는 DAG를 함께 보여줍니다.
설정은 계정별로 PostgreSQL에 저장됩니다.

화면은 **내 대시보드 제목 → 공통 조회 범위·조건과 갱신 → 담당 DAG / 차트·추세 탭 → 본문**
순서로 배치됩니다. 공통 영역의 조건은 같은 계정에 저장되고 탭 이동 후에도 유지됩니다.

- **DAG 검색**: 담당 범위 안에서 ID·표시 이름·업무 태그·소유자를 검색합니다.
  공백으로 나눈 단어를 모두 포함해야 합니다. 검색은 담당 DAG 등록 범위를 늘리지 않습니다.
- **실행 상태 / DAG 운영 상태 / 조회 기간**: 실패·실행 중·대기·성공과 활성·일시중지를
  별개로 선택합니다. 조건을 입력한 뒤 **적용** 또는 Enter를 누릅니다.
- **검색 필터 초기화**: 검색어와 상태 조건만 초기화합니다. 담당 DAG·태그 등록과 기간은 유지합니다.
- **자동 토글 / 갱신 아이콘**: 자동 조회를 켜거나 끄고 30초·1분·5분 간격을 선택합니다.
  수동 아이콘은 자동 조회가 꺼져 있어도 작동합니다. 새로고침은 짧은 서버 캐시를 재사용할 수 있습니다.
  숨겨진 탭과 필터 입력·패널 편집 중에는 주기 조회를 쉬며, 끈 설정은 두 탭에서 유지됩니다.

주의가 필요한 실행과 담당 DAG를 나란히 표시하고 최근 실행은 아래에 표시합니다.
넓은 화면에서는 세 영역을 한 행에, 좁은 화면에서는 한 열에 배치합니다.
각 영역은 목록 안에서 스크롤하므로 다른 영역의 위치를 유지하면서 확인할 수 있습니다.

- 실패·실행 중·대기·성공 건수와 마지막 성공, 최근 실행을 확인합니다.
- 오래 실행 중인 작업의 기준 시간은 담당 범위 설정에서 지정합니다. 기본 자동 갱신은 30초입니다.
- **실행·로그 열기**로 Airflow 실행 상세에 이동합니다.
- **활성화 / 일시중지**에서 현재 상태와 스케줄을 확인한 뒤 운영 상태를 바꿉니다.
  활성화하면 스케줄·catchup·대기 실행에 따라 작업이 시작될 수 있습니다.
  일시중지는 이미 실행 중인 태스크를 강제 종료하는 기능이 아닙니다.
- 실패한 실행의 **재실행 대상 확인**에서 태스크를 확인한 뒤 요청합니다.
  해당 기존 실행의 실패·upstream_failed 태스크만 재실행합니다. 성공한 태스크,
  다른 실행과 기존 DAG 버전은 유지합니다. 새 실행은 **DAG 상세·새 실행**에서 만듭니다.

재실행에는 해당 DAG 태스크의 변경 권한, 활성화·일시중지에는 DAG 변경 권한이 필요합니다.
일시중지된 DAG는 담당 DAG 영역에서 활성화한 후 재실행할 수 있습니다.
Model Lab의 외부 작업과 관리 DAG는 Model Lab에서 처리하도록 안내합니다.

## 내 대시보드 · 차트·추세

기본 **분석 범위 → 담당 DAG와 공유**에서는 담당 탭의 DAG·태그·검색·상태·기간을 사용합니다.
범위가 비어도 전체 DAG로 넓히지 않습니다. 담당 DAG의 실행 상태·조치는 첫 탭에서,
동일한 범위의 기간별 추세는 이 탭에서 확인합니다. 기본 차트가 제공되며 필요할 때 편집합니다.
Airflow 실행 이력 표의 DAG·Run ID를 클릭하면 해당 Airflow 상세·로그 화면으로 이동합니다.

공통 범위 안에서 패널별 추가 필터와 변수를 적용합니다. 기존 `dag` 변수에 값이 있으면
**추가 DAG 조건**으로 표시합니다. 임의 SQL·Model Lab 기록처럼 담당 DAG에 자동 연결할 수 없는
데이터소스는 공유 모드에서 조회를 막고 **별도 분석**을 안내합니다. 별도 분석은 보드의 기간·변수와
기존 데이터소스 권한을 사용합니다. 분석 범위 변경을 영구 유지하려면 보드 편집에서 저장합니다.

담당 탭은 기간 밖의 진행 중 실행도 표시하지만 차트는 선택 기간의 실행 이력을 분석합니다.
따라서 장기 실행·대기 작업이 기간 경계를 넘으면 진행 중 건수가 다를 수 있습니다.

로그인한 Airflow 계정마다 대시보드를 구성하고 저장합니다. **내 대시보드**에서 보드를
선택하며 마지막으로 열었던 보드는 다음 접속에 복원됩니다. 다른 계정의 개인 구성과 분리됩니다.

1. **대시보드 편집**을 누르고 패널을 추가합니다.
2. 패널에서 데이터소스와 조회할 데이터셋을 선택합니다. 필터·그룹·집계·시간 구간을
   설정하고 미리보기로 결과를 확인합니다. 설정된 PostgreSQL 조회 소스는 SQL 편집도 지원합니다.
3. 선·영역·막대·숫자·게이지·도넛·테이블·산점도·히트맵 중 표시 방식을 선택합니다.
   축·범례·시리즈·단위·소수점·임계값·색상 등의 옵션을 조정할 수 있습니다.
4. 패널을 드래그해 배치하고 크기를 조절한 뒤 **저장**합니다. 패널에 변경을 적용하는 것과
   대시보드를 영구 저장하는 것은 구분됩니다.

패널마다 여러 쿼리를 구성할 수 있으며, **데이터 확인**에서 실제 조회 결과를 볼 수 있습니다.
카테고리·변수·조회 기간, JSON 가져오기/내보내기, 패널 템플릿,
최근 20개 저장 이력 복원도 지원합니다. 같은 보드를 두 창에서 동시에 수정하면
다른 창의 저장을 덮어쓰지 않고 충돌을 알립니다.

차트는 ECharts, 드래그 배치는 GridStack, SQL 편집은 CodeMirror를 플러그인에 포함해
제공합니다. 별도 Grafana·Prometheus 서버는 필요하지 않습니다.

## 운영 모니터링

관리자는 **연결 설정 → 화면 추가**에서 완성된 운영 대시보드의 이름과 URL을 등록합니다.
여러 화면을 등록하면 메뉴 안에서 선택할 수 있습니다. 현재는 연결할 URL이 없어 미등록
안내 화면입니다. 외부 화면 제작·데이터 수집·서버 설치는 플러그인이 수행하지 않습니다.

외부 로그인이 필요하면 **원본 열기**에서 로그인한 뒤 새로고침합니다. 실제 조회 권한과
Airflow 출처의 iframe 허용은 외부 서비스에서 설정해야 합니다. Airflow 계정과 외부 계정의
SSO·권한을 자동 연결하지 않습니다. Grafana URL은 선택적으로 Airflow의 Light/Dark 테마를
따르게 할 수 있고, 다른 서비스는 외부 화면의 테마를 사용합니다.

운영 설정과 인증 조건의 상세 설명은 [개인 업무와 운영 모니터링 안내](WORKSPACES.md)에 있습니다.

## Model Lab

프로젝트별로 **평가셋 → 기준선 → 개선 후보 → 재평가 → 모델 검토 → 적용 구성**을 연결합니다.
현재 화면과 설치·실행 조건은 [Model Lab 작업 안내](MODEL_LAB.md)를 참고하세요.

- **개요**: 준비 상태와 다음 행동을 확인합니다.
- **데이터·평가셋**: JSON 가져오기나 질문 한 개로 시작하고 새 버전을 저장합니다.
- **실험**: 기준선과 후보를 평가하거나 같은 실험에 외부 학습을 연결합니다.
- **실행**: DAG 진행·응답·검색 순위·사례별 사람 검토와 기준선 비교를 확인합니다.
- **모델·적용 구성**: 평가한 모델 버전을 검토하고 서비스에 전달할 구성 JSON을 저장합니다.
- **저장소**: 실행 환경별 학습 데이터·원본 모델·결과 경로를 저장하고 접근을 확인합니다. 학습 레시피에서 선택하며 실행마다 경로와 프로필 버전을 고정합니다.
- **환경·연결**: 추론 Connection·평가 DAG·Pool·HTTP/Kubernetes 학습 환경과 프로젝트 권한을 관리합니다.

현재 `챗봇 모델 개발` 프로젝트에는 질문 해석 16개와 가상 근거 답변 6개의 QA 초안이 있습니다.
검토 전 초안의 기대값을 확정된 정답으로 채점하지 않습니다. 실행 상세에서 사람 검토를 기록할 수 있습니다.
실제 검색/DW의 정답·데이터는 별도 준비가 필요합니다.

## 실행과 저장 위치

| 데이터·작업 | 위치 |
|---|---|
| 프로젝트·실험·평가셋 버전·모델·검토·초안 | 같은 Airflow PostgreSQL의 workbench 스키마 |
| DAG 상태 | 상세·제어는 인증된 Airflow API, 대시보드 통계는 동일 DAG 권한으로 PostgreSQL 집계 |
| 생성·임베딩 계산 | 선택한 추론 서버 |
| 평가 상세 결과 | API·triggerer·task가 공유하는 artifact 볼륨 |
| 학습 | 외부 HTTP 실행기 또는 Kubernetes Pod |
| 워커 작업·예약 | 기존 상태 API를 거쳐 같은 PostgreSQL |

워커용 DB 계정은 추가하지 않습니다. 프로젝트의 viewer/developer/manager 역할과 실제 Airflow DAG 권한을 함께 검사합니다.
환경과 Connection 설정 변경은 Workbench 관리자 권한을 요구합니다. 개인 대시보드 소유권과 프로젝트 협업 권한은 구분됩니다.

## 검증과 범위

[Model Lab 검증 기록](../../../docs/qa/model-lab-workflow-2026-09-10.md)에 자동 테스트와 실제 Qwen·BGE 실행 결과를 정리했습니다.
기존 개인 대시보드·테마 연동·외부 GPU 진단 기능을 유지합니다.

현재 로컬 control 워커는 실제 학습 전에 학습 패키지·원본 가중치·데이터와 RAM 준비가 필요합니다.
이번 검증에서 파인튜닝을 수행하지 않았습니다. 학습 산출물의 자동 변환, 서비스 자동 배포·재색인·운영 적용 확인·자동 롤백은 아직 제공하지 않습니다.
모델의 적용 구성과 이전 구성 내보내기를 프로젝트 배포 절차에 사용할 수 있습니다.
